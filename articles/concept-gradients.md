Training a model is an optimization problem. A *loss* measures how far the model's output is from the desired one; a *gradient* is the vector of partial derivatives telling each parameter which way, and how much, to change to reduce that loss. Optimization repeatedly nudges the parameters along these gradients. This concept builds on [weights, parameters and activations](../nodes/concept-parameters.md), since gradients are computed with respect to those parameters (and sometimes with respect to inputs).

The security-relevant twist is *visibility*. Gradients are ordinarily a training-time internal, but the same machinery can be turned against a model or its data. If an attacker can compute gradients with respect to an input, they can search for perturbations that change the output; if they can observe gradients or updates shared during training, those signals can leak information about the data that produced them.

That is why this concept is a prerequisite for a spread of techniques: [gradient-based adversarial perturbations / FGSM](../nodes/attack-fgsm.md) and [gradient-guided adversarial suffixes](../nodes/attack-gcg.md) use gradients to craft inputs, while [reconstruction from gradients or updates](../nodes/attack-gradient-leak.md) exploits their leakage. It also underpins [pretraining](../nodes/life-pretrain.md) and the countermeasure [differentially private training](../nodes/defense-dp.md). Whether any given leakage or attack succeeds depends on access and setup, which the cited sources address.
