Authorization-aware retrieval filters candidate documents by the requesting principal's access rights before any content is disclosed, and preserves access metadata through the retrieval and generation stages so that permission is enforced end to end. It applies to [retrieval-augmented generation](../nodes/system-rag.md), where a model is grounded on documents fetched from a corpus. Rather than retrieving broadly and hoping the model withholds what a user should not see, the control excludes unauthorized documents from the candidate set in the first place.

As a mitigation it is conditional. It can reduce [unauthorized retrieved-document disclosure](../nodes/attack-rag-disclosure.md) and [cross-session or cross-tenant disclosure](../nodes/attack-session-leak.md) by ensuring retrieval respects the same access controls as the underlying data. Residual risk remains: if permission metadata is stale, if access checks are applied at the wrong stage, or if content is duplicated into indexes that lose their access labels, disclosure can still occur. It governs which documents are eligible for retrieval, not what a model infers from documents a user is legitimately allowed to see.

Enforcing access at retrieval time complements out-of-model authorization on the surrounding actions. Consult the cited application-security guidance for how access controls should follow data into the retrieval pipeline.
