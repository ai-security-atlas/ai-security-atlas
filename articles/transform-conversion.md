Checkpoint conversion and sharding repackage a model's stored representation and metadata without changing what the model computes. Conversion translates weights between serialization formats or runtime layouts, while sharding splits a large checkpoint into multiple files so it can be distributed, downloaded or loaded in parts. Reference material includes the *GGUF format specification* and *Safetensors documentation*.

The operation works over a model's [weights, parameters and activations](../nodes/concept-parameters.md), reorganizing how they are laid out on disk. It underlies a number of concrete model formats, including [GGUF](../nodes/format-gguf.md), [ONNX](../nodes/format-onnx.md), [PyTorch checkpoints and pickle-related loading](../nodes/format-pytorch.md), [Safetensors](../nodes/format-safetensors.md) and the broader [complete model package](../nodes/format-model-package.md), since moving between these requires conversion.

As its summary notes, compatibility and integrity are separate questions from the repackaging itself. Conversion is neutral, but it is relevant to security because it can be used by [behavioral tampering through merges or conversion](../nodes/attack-merge-tamper.md), and because some formats carry loading-time execution risks that make provenance and verification matter. Format-specific details, including how each layout stores tensors and metadata, are left to the cited sources.
