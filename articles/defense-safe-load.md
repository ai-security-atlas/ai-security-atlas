Safer tensor loading and dependency control favor constrained serialization formats and audited loaders over formats that can execute arbitrary code when a model is loaded, while retaining parser and behavioral checks on the loaded artifact. It applies to [model loaders and executable repository code](../nodes/system-loader.md), where deserializing a checkpoint from an untrusted source can trigger code execution. The control prefers formats that carry data rather than executable objects and restricts the code paths and dependencies invoked during loading.

As a mitigation it is conditional. It can reduce [unsafe checkpoint deserialization](../nodes/attack-unsafe-load.md) by removing the general code-execution capability that unsafe formats expose at load time. Residual risk remains: a safer format constrains deserialization but does not vouch for the model's behavior, vulnerabilities can exist in loaders and parsers themselves, and dependencies pulled in during loading remain part of the attack surface — which is why parser and behavioral checks are still needed.

Because it addresses the load step rather than what runs afterward, it pairs with execution isolation to contain anything that still executes. Consult the cited serialization documentation and loader security warnings for the format distinctions and known pitfalls this control is built around.
