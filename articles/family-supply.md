This family groups techniques that compromise the components around a model—loaders, artifacts, dependencies, and hosting—rather than the model's learned behavior. The unifying objective is *Compromise the surrounding execution environment*, and in some cases *Establish persistent attacker influence*, by subverting how a model is packaged, delivered, or run.

Members target the delivery and execution path. [Unsafe checkpoint deserialization](../nodes/attack-unsafe-load.md) abuses formats that can execute code when a checkpoint is loaded. [Artifact, adapter or configuration substitution](../nodes/attack-artifact-substitution.md) swaps a trusted file for an attacker's version, and [Malicious dependencies or repository code](../nodes/attack-dependency.md) reaches the system through the software supply chain that surrounds model code.

The atlas marks unsafe deserialization as distinct from Trigger-conditioned model backdoors: both involve a compromised artifact, but this family concerns a code-execution flaw in how the artifact is read or loaded, whereas a backdoor is malicious behavior learned into the weights themselves. Use the grouping to reason about classic software and infrastructure security as it applies to AI systems—many members mirror conventional supply-chain risks, and their mitigations often come from established software-integrity practice rather than from model robustness.
