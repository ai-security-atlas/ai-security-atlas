Quantization changes the numerical representation of a model's values, for example moving weights from higher-precision floating point to lower-bit integers, often with a calibration step that chooses scaling so accuracy is preserved. The payoff is a smaller memory footprint and faster, cheaper inference, which is why it is a routine step in deploying large models. Reference methods include *GPTQ: Accurate Post-Training Quantization for Generative Pre-trained Transformers* and *QLoRA: Efficient Finetuning of Quantized LLMs*.

The technique works over a model's [weights, parameters and activations](../nodes/concept-parameters.md), altering how each value is stored and computed. As its summary notes, quantization is separate from serialization and from training stage: it is a numerical transformation, not a file format and not a fine-tuning objective. It is therefore distinct from [GGUF](../nodes/format-gguf.md), which is a storage format that may hold quantized weights rather than a quantization method itself.

Quantization underpins more specific methods, including [GPTQ](../nodes/transform-gptq.md), a concrete post-training scheme, and [QLoRA](../nodes/adapt-qlora.md), which fine-tunes low-rank adapters over quantized base weights. It is a neutral engineering technique; the accuracy retained at a given bit width is an empirical question left to the cited sources.
