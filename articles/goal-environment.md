This objective concerns attacks that reach past the model to the machinery around it — the loaders, packages, plugins, build systems and integrations that run, serve or distribute an AI system. The attacker's aim is not to change a single answer but to compromise the host, the pipeline or the distribution channel, often gaining code execution or a foothold that outlasts any one request.

The techniques that route here treat AI artifacts and their supporting software as an attack surface. [Unsafe checkpoint deserialization](../nodes/attack-unsafe-load.md) abuses model file formats that execute code when loaded. [Artifact, adapter or configuration substitution](../nodes/attack-artifact-substitution.md) swaps a trusted component for a malicious one somewhere along the supply chain. [Malicious dependencies or repository code](../nodes/attack-dependency.md) plant harmful behavior in the packages and code a project pulls in. [Improper handling of model-generated output](../nodes/attack-output-sink.md) matters here when generated text flows unchecked into a shell, database or eval-like sink and becomes execution.

What unifies them is that the payload lands in the *environment* — the process, the filesystem, the build — rather than in the model's reasoning. This is closely related to establishing persistence, but the emphasis here is on compromising the surrounding system in the first place. For the specific formats, loaders and supply-chain paths involved, see the linked techniques.
