Mixture-of-experts (MoE) models replace a dense layer with many parallel "expert" sub-networks plus a router that, for each input, activates only a small subset. Built on [Neural networks](../nodes/arch-neural.md), this sparse routing lets total parameter count grow substantially while the compute per token stays bounded, because only the selected experts run. The atlas frames MoE as a component-level design choice rather than a standalone model family: sparse expert routing can coexist with a transformer backbone or other architectures, layered into an existing design rather than replacing it.

## Why it matters for security analysis

Because MoE is a routing mechanism inside a larger model, security analysis should not treat it as its own end-to-end system. The properties that matter are inherited from whatever backbone hosts it, while the routing layer adds specific considerations of its own — for instance, that inputs are handled by data-dependent subsets of parameters and that the router's behavior mediates which experts see which tokens. This node carries no relevant-technique edges of its own, so applicable scope is reasoned from the host architecture and from model-level concerns inherited via [Neural networks](../nodes/arch-neural.md), evaluated against the concrete deployment. Design and empirical specifics, including routing behavior and its consequences, are deferred to the cited literature.
