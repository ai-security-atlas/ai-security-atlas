Tokenization is the step that converts raw text into the discrete units a model actually consumes. A *tokenizer* splits input into tokens drawn from a fixed *vocabulary* — often subword fragments rather than whole words — and maps each to an integer id. *Special tokens* mark structure the model relies on, such as sequence boundaries, padding, or role delimiters. Together these define the model's input contract: the exact way strings must be segmented and encoded for the model to interpret them as intended. This concept builds on [neural networks](../nodes/arch-neural.md), which operate on the resulting token ids.

The practical consequence is that the same text can map to different token sequences under different tokenizers, and that special tokens carry meaning beyond their surface characters. Because tokenization sits at the boundary between human-readable text and model input, it is where several concerns become concrete.

This concept is a prerequisite for [gradient-guided adversarial suffixes](../nodes/attack-gcg.md), which search over tokens to construct an input, and it is part of the [complete model package](../nodes/format-model-package.md), since a model's tokenizer and vocabulary must ship alongside its weights for outputs to be reproduced faithfully. A mismatched or misunderstood tokenizer breaks that contract; how specific techniques exploit tokenization is left to those nodes and their cited sources.
