Logits are the raw, pre-softmax scores a model assigns to each candidate token before they are normalized into a probability distribution. Applying the softmax function turns logits into probabilities; decoding then selects a token from that distribution. Logits and probabilities are the model's most granular observable signal about what it "thinks" comes next. This concept builds on [weights, parameters and activations](../nodes/concept-parameters.md), since these scores are the output of the final projection over learned weights.

What makes this concept security-relevant is *output granularity*. An API might return full per-token probabilities, only the top few candidates, a single sampled token, or just plain text. Each level of exposure changes what an observer can infer or optimize against: richer numerical output offers more signal, while text-only output offers less. The interface's design, not just the model, sets this boundary.

Consequently, logits are a prerequisite for techniques that exploit observable output, including [black-box functional model extraction](../nodes/attack-model-imitation.md), [membership inference](../nodes/attack-membership.md), [model inversion and attribute inference](../nodes/attack-attribute.md), [language-model training-data extraction](../nodes/attack-training-extraction.md), and [partial parameter recovery from API behavior](../nodes/attack-projection-theft.md). They also feed [sampling and decoding configuration](../nodes/concept-decoding.md). How much any exposure level actually enables is empirical and belongs to the cited sources.
