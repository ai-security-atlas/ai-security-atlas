Persistent agent-memory poisoning plants or induces stored entries that later redirect an agent's tasks or decisions. It routes toward [causing unauthorized actions or privilege use](../nodes/goal-actions.md) and [establishing persistent attacker influence](../nodes/goal-persistence.md), with the defining property that the influence outlives the moment it was introduced.

Conceptually the technique combines [indirect prompt injection](../nodes/attack-indirect-injection.md), which delivers the malicious content, with the existence of [persistent agent memory](../nodes/system-memory.md), which stores it for reuse. The attacker-controlled input is the content that gets written into memory; the victim-controlled state is the memory store and every future session that reads it back as trusted context. It may also be enabled by [RAG knowledge-base poisoning](../nodes/attack-rag-poison.md), and in turn it can enable further indirect injection when poisoned memory is re-ingested.

The load-bearing evidentiary point is persistence: it must be demonstrated across sessions. A single instruction taking effect within one prompt is not sufficient evidence of memory poisoning — the claim is precisely that the effect survives into later, independent runs on a [tool-using agent](../nodes/system-agent.md).

Candidate mitigations reduce but do not eliminate risk: [memory provenance, review and expiry](../nodes/defense-memory.md) to constrain what persists and for how long, and [auditable action and content lineage](../nodes/defense-logging.md) to trace where a stored entry came from. Evaluation is framed through the [AgentDojo benchmark](../nodes/eval-agentdojo.md), [attack success and severity](../nodes/eval-asr.md), and an [explicit threat model](../nodes/eval-threat-model.md). For demonstrated cross-session persistence, defer to the cited source.
