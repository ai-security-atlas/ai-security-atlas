Context-specific output validation treats a model's generated code, markup, and queries as untrusted input and validates or encodes it at the point where it is finally used — its sink — rather than trusting it because a model produced it. It rests on clear [trust boundaries and authorization](../nodes/concept-boundaries.md): model output crossing into an interpreter, browser, shell, or database is subject to the same escaping, parameterization, and validation any external input would receive at that specific sink.

As a mitigation it is conditional. It can reduce [improper handling of model-generated output](../nodes/attack-output-sink.md) by neutralizing injected or malformed content before it reaches an executor, applying the encoding appropriate to each destination. Its effectiveness depends on completeness: every sink must be covered with the correct context-specific handling, and a missed sink, a wrong encoding, or a sink that cannot be safely parameterized reopens the exposure. It addresses how output is consumed, not whether the model was manipulated into producing it.

Because it acts at the boundary of execution, it pairs well with execution isolation, which contains whatever slips through. This mirrors long-standing output-encoding practice from application security. Consult the cited application-security guidance for sink-specific handling.
