Encoder-decoder models separate two stages: an encoder builds a representation of the full source input, and a decoder generates an output sequence conditioned on that representation. Built on [Transformers](../nodes/arch-transformer.md), this design suits mappings from one sequence to another — translation, summarization, and other text-to-text tasks — where the output should reflect the entire input rather than only a running prefix. The encoder can attend bidirectionally over the source, while the decoder generates autoregressively and cross-attends to the encoded source.

## Why it matters for security analysis

The split conditioning changes the threat surface relative to a purely decoder-only model. There are two distinct input pathways — the source fed to the encoder and any prompt or prefix guiding the decoder — and analysis should be clear about which one an attacker influences and what the model is asked to produce. Techniques framed strictly around a single autoregressive context window do not map cleanly onto an architecture whose generation is conditioned on a separately encoded source. This node carries no relevant-technique edges of its own, so applicability is best reasoned from the concrete task and deployment. It should be distinguished from [encoder-only language models](../nodes/arch-encoder.md), which produce representations without a generative decoder, and from [decoder-only autoregressive language models](../nodes/arch-decoder.md). Design and empirical specifics are deferred to the cited literature.
