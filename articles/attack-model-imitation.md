Black-box functional model extraction trains a substitute model to imitate a target's behavior using only the outputs returned to queries. It routes toward [appropriating model artifacts or capabilities](../nodes/goal-model-theft.md): the aim is to reproduce what the target *does*, not to steal its files.

Conceptually the technique treats the target as a labeling oracle. It depends on access to [logits, probabilities and observable outputs](../nodes/concept-logits.md) — richer outputs make imitation easier — and on [knowledge distillation](../nodes/adapt-distillation.md) to fit a student to the collected query-response pairs. The attacker-controlled input is the query set and the substitute's training; the victim-controlled state is the [classical predictive ML](../nodes/arch-classical.md) or [neural network](../nodes/arch-neural.md) model exposed through a query interface. The defining caveat is that functional fidelity is not equality of weights, and that query rights and licensing are separate policy questions from the technical result.

It is distinct from [unauthorized checkpoint or adapter theft](../nodes/attack-weight-theft.md), which takes the actual artifact rather than approximating its function, and it serves as a prerequisite for [unauthorized teacher-student capability transfer](../nodes/attack-distillation-theft.md).

The atlas lists no dedicated mitigation node on this entry; query monitoring, rate and output limits, and access policy are the natural references. Evaluation is framed through [attack success and severity](../nodes/eval-asr.md), an [explicit threat model](../nodes/eval-threat-model.md), and [extraction fidelity versus artifact equality](../nodes/eval-fidelity.md). For measured fidelity and query cost, defer to the cited sources.
