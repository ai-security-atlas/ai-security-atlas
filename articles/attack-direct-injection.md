Direct prompt injection is an attempt by an attacker who can address the model directly to supply instructions that override the application's intended task or trust policy. It routes toward [causing unauthorized actions or privilege use](../nodes/goal-actions.md) and [violating intended behavioral constraints](../nodes/goal-behavior.md).

Conceptually the technique exploits [context windows and in-context learning](../nodes/concept-context.md): because instructions and data share one context, attacker text placed there can compete with the application's own directives. It also turns on [trust boundaries and authorization](../nodes/concept-boundaries.md). The attacker-controlled input is the injected instruction; the victim-controlled state is the system prompt, task framing, and any tools the application exposes. A load-bearing caveat is that direct access to the input does not imply control over privileged system messages — the attacker submits text, but does not thereby author the operator's higher-trust instructions.

The important sibling distinction is with [indirect prompt injection](../nodes/attack-indirect-injection.md): there the malicious instruction arrives inside lower-trust content the system ingests, whereas here the attacker speaks to the model directly. Both live in the prompt-and-context-manipulation family and apply to [language models](../nodes/arch-decoder.md) and [tool-using agents](../nodes/system-agent.md).

The candidate mitigation is to [separate data from authority](../nodes/defense-boundaries.md) so that content in the context window is not automatically treated as a command; this reduces but does not eliminate the risk. Evaluation is framed through [attack success and severity](../nodes/eval-asr.md) under an [explicit threat model](../nodes/eval-threat-model.md). For measured effectiveness against specific applications, defer to the cited sources.
