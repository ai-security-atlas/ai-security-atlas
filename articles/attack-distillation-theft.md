This technique applies distillation or imitation to acquire a model's capabilities without the permission that would normally be required, routing toward [appropriating model artifacts or capabilities](../nodes/goal-model-theft.md). The essential framing is that distillation itself is neutral engineering; the adversarial label depends on authorization and use, not on the algorithm's name.

Conceptually it composes two prerequisites: [black-box functional model extraction](../nodes/attack-model-imitation.md), which queries a target to gather input-output behavior, and [knowledge distillation](../nodes/adapt-distillation.md), which trains a student to reproduce that behavior. The attacker-controlled input is the query set and the training of the student; the victim-controlled state is the target model exposed through an interface that answers those queries. The result is a substitute that approximates the target's function.

Because it builds directly on functional extraction, the two are easy to conflate — the distinguishing element here is the explicit teacher-student transfer and the authorization question layered on top. A learner should also remember that acquiring function is separate from acquiring the original weights.

The atlas lists no dedicated mitigation node for this entry; defenses discussed for functional extraction (such as query monitoring and access policy) are the natural reference point. Evaluation is framed through [attack success and severity](../nodes/eval-asr.md), an [explicit threat model](../nodes/eval-threat-model.md), and [extraction fidelity versus artifact equality](../nodes/eval-fidelity.md) — the last stressing that a faithful function is not the same as an identical model. This attack sits in the model-theft family. For measured fidelity, defer to the cited sources.
