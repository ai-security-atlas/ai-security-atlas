This objective covers attacks whose payoff is *action*: getting an AI system to invoke tools, read data or make changes that its operator never authorized. It matters most for agents and applications wired to real capabilities — connectors, APIs, file systems, payment or messaging tools — where a single redirected step can have consequences beyond the text of a reply.

What unifies the techniques that route here is that they all corrupt the boundary between trusted instructions and untrusted content. [Direct prompt injection](../nodes/attack-direct-injection.md) and [indirect prompt injection](../nodes/attack-indirect-injection.md) smuggle attacker instructions into the model's context, while [instructions carried through multimodal content](../nodes/attack-multimodal-injection.md) do the same through images or other media. Others abuse the agent's own machinery: [confused-deputy abuse](../nodes/attack-confused-deputy.md) borrows the agent's privileges, [exploitation of excessive delegated agency](../nodes/attack-excessive-agency.md) leans on over-broad permissions, and [tool-description poisoning](../nodes/attack-tool-description.md), [tool-output injection](../nodes/attack-tool-output.md) and [tool definition changes after approval](../nodes/attack-tool-rugpull.md) tamper with the tool layer itself. Inter-agent message manipulation, persistent memory poisoning and improper handling of model output can carry the same effect across turns or components.

Think of this objective as "who acted, with whose authority" rather than "what was said." For mechanics and preconditions, follow the individual techniques listed above.
